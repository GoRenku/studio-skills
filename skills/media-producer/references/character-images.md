# Character Reference Images

For a new standalone reference generated by Renku, use `image.create` with target `project`. The run output is an exact project-relative file; reuse it as a `project-file` reference until a current focused destination explicitly attaches it.

For a user, Codex, or other external image, stage the accepted file inside the project and use the exact normalized `project-file` reference. Do not invent a generation spec, receipt, asset id, or asset-file id.

For a localized revision of a registered image, use `image.edit` targeting `asset:<asset-id>`. Preserve the exact `source/source-image` placement returned by context and assign it to a real media `providerField` from the selected edit endpoint. Optional Cast, Location, Lookbook, and Additional References come from the same context guide.

Do not build collages to simulate multiple references. Do not put local absolute paths or provider URLs in selections. If the user needs a durable generic Cast reference attachment and no current focused command owns it, report that capability gap instead of inventing an attachment workflow.
